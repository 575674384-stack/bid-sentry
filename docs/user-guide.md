# Bid Sentry 用户说明

## 1. 元数据安全重置

1. 进入“隐私清洗”，选择一个或多个 DOCX/PDF，再选择输出目录。
2. 点击“生成清洗预览”。表格按文件、部件和字段显示清洗前原值以及本次实际使用的随机新值。
3. 阅读预览并勾选确认。原值和随机值只留在当前任务内存，不会写入报告或历史。
4. 点击“开始安全清洗”。只有验证通过的新文件会发布到输出目录；原文件不会被覆盖。

签名、加密、损坏或不支持的文件会被拒绝。若失败，记录错误码、阶段和诊断编号即可反馈，不要上传原始标书。

## 2. 对照审查

1. 进入“对照审查”，分别选择招标文件和投标文件，并选择报告目录。
2. 填写并确认投标单位名称。它用于区分招标人、投标人和正文中的其他主体。
3. 可选勾选 AI 辅助。界面会说明目标主机、模型和发送边界；只有确认后才会向用户配置的接口发送截断文本和结构锚点。
4. 查看本机规则和 AI 辅助 finding。`error` 必须同时有双方证据；AI 结果最高只能是“需人工复核”。
5. 打开生成的 JSON/HTML 报告，结合原始文件逐条人工确认。工具不会自动修改或提交投标文件。

对照审查只接受 DOCX 和有可靠文本层的 PDF。扫描 PDF 会提示 OCR 暂不支持。

## 3. 资格标预制作

1. 进入“资格标预制作”，选择招标文件和输出目录。
2. 填写投标单位、统一社会信用代码、地址、法定代表人/授权代表、联系人、电话、电子邮箱、项目/标段和编制日期。
3. 点击识别模板，逐一查看候选章节、起止范围和理由；必须确认使用的模板，不会静默套用整份文件。
4. 查看填充计划：`tender-fixed` 必须有招标证据，`user-form` 来自本页表单，图片/证照/签章为占位符，未知项不会被猜测。
5. 点击生成 DOCX 草稿。生成结果会重新读取和检查；打开后检查中文字体、表格、页眉页脚、分页和所有占位符，再决定是否继续编辑。

DOCX 招标模板优先保留原结构；PDF 仅做可解释的结构化重建，报告会显示版式差异警告。

## 4. AI 设置

在“AI 设置”填写 OpenAI 兼容 Base URL、模型、超时、并发和 API Key。远程 URL 必须 HTTPS；本机环回地址可用 HTTP。测试连接只调用 `/models`，不上传文档。

API Key 不会在界面回显；系统支持加密存储时才跨会话保存，否则只在当前会话可用。清除 Key 后，旧密钥不能恢复。

## 5. 托盘与更新

- “关闭窗口时最小化到系统托盘”默认关闭。启用后关闭窗口会隐藏，托盘菜单可显示窗口或退出；托盘宿主不可用时应用回退为正常关闭。
- “启动后检查 GitHub Releases 更新”默认开启。检查本身不下载；发现新版后点击下载，再点击打开安装程序。portable/DEB 等包型需打开官方 Releases 页面手动安装。
- 更新只访问固定的官方仓库，Release notes 作为不可信纯文本显示。未签名安装包请先核对 SHA-256。

## 6. 诊断与隐私

设置页“打开诊断目录”只打开本机脱敏 JSONL。诊断不会包含路径、正文、元数据原值/随机值、API Key、堆栈或完整网络响应。需要报告问题时，只提供错误码、阶段和诊断编号，并说明操作系统和版本。
